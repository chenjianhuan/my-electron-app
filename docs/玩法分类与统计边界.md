# 玩法分类与统计边界

## 目标

这份文档只解决一件事：

- 面对 [数据集](/Users/wangci/my-electron-app/docs/数据集) 里的真实消息，哪些内容应该进入`号码统计`
- 哪些内容应识别为`玩法单`
- 哪些内容只是`上下文/噪音`
- 哪些内容属于`歧义 shorthand`，需要单独补规则

本文件先定语义边界，不定 UI，不定最终代码结构。

## 统计目标

建议把统计对象拆成两层：

1. `号码统计`
   只接收可以安全展开为号码集合的普通单。

2. `玩法统计`
   接收`特`、`平`、`连`、`二中二`等不能安全展开为号码统计的玩法单。

当前阶段如果某类玩法`不开放`，也不应偷偷按普通号码单入账；应当识别出来并拦截，至少标记为`未开放玩法`。

## 分类总表

| 分类 | 是否进入号码统计 | 当前建议 |
| --- | --- | --- |
| 普通号码单 | 是 | 正常解析并展开 |
| 普通生肖/属性单 | 是 | 正常解析并展开 |
| 地区/上下文行 | 否 | 改变后续上下文 |
| 摘要/噪音行 | 否 | 直接忽略 |
| 玩法单（特/平/连/二中二等） | 否 | 单独识别，不混入号码统计 |
| 歧义 shorthand | 视规则而定 | 补专门规则后再入账 |

## A 类：可安全展开为号码统计

### A1. 显式号码 + 金额

这类本质是`号码集合 + 金额`，可直接展开。

样例：

- [29-35-36-41-47-48各号10](/Users/wangci/my-electron-app/docs/数据集#L770)
- [02.10.08.18.20.26.28.39.40.41.47各号10](/Users/wangci/my-electron-app/docs/数据集#L774)
- [25，37，16，40，29，41，30，42，19，31，23，35，38，43各数10](/Users/wangci/my-electron-app/docs/数据集#L794)
- [15.27.20.44.01.11.35.14各一百](/Users/wangci/my-electron-app/docs/数据集#L831)
- [38五十](/Users/wangci/my-electron-app/docs/数据集#L811)

### A2. 生肖单

只要语义仍然是“该生肖对应号码各多少”，就可展开。

样例：

- [兔各号20](/Users/wangci/my-electron-app/docs/数据集#L771)
- [蛇兔各号20](/Users/wangci/my-electron-app/docs/数据集#L790)

### A3. 属性单

### A4. 组合普通单，但仍按并集展开

这类消息同时出现多个普通目标，但仍然是“每个命中号各金额”。

样例：

- [单➕猪兔各号10](/Users/wangci/my-electron-app/docs/数据集#L772)
- [龙虎鼠各数20](/Users/wangci/my-electron-app/docs/数据集#L803)

处理建议：

- 多个普通目标默认按项目既有的“属性叠加策略”处理
- 如果是明显并列口语，如 `龙，鸡，蛇`，按并集更符合真实消息

## B 类：玩法单，不能混入号码统计

### B1. 平类

包括：

- `平特一肖`
- `平特`
- `平肖`
- `平龙/平虎/平狗` 这类简写

样例：

- [平特一肖牛200](/Users/wangci/my-electron-app/docs/数据集#L6)
- [平龙8000](/Users/wangci/my-electron-app/docs/数据集#L77)
- [平特 羊 100米](/Users/wangci/my-electron-app/docs/数据集#L152)
- [平特  狗  100米](/Users/wangci/my-electron-app/docs/数据集#L177)

当前结论：

- 这类不是普通生肖号各多少钱
- 如果当前不开放，必须识别后拦截，不得降级成普通生肖单

### B2. 特类

只要带`特`，通常语义已不是普通号码集合。

样例：

- [特01.13.25.07.19.31.02.14.26.08.20.32.09.05.17.29.21.33.45.44.各25](/Users/wangci/my-electron-app/docs/数据集#L785)
- [特码兰波单数一个号二十](/Users/wangci/my-electron-app/docs/数据集#L208)

当前结论：

- 不应按普通号码单直接入号码统计
- 应先识别为`特码相关玩法`

### B3. 连类

包括：

- `三连`
- `四连`
- `四连肖`
- `五连肖复式`

样例：

- [猴  鼠 猪 马 四连    10元](/Users/wangci/my-electron-app/docs/数据集#L146)
- [三连 马虎龙 马猪龙 各10](/Users/wangci/my-electron-app/docs/数据集#L167)
- [四连 马虎龙猪 10](/Users/wangci/my-electron-app/docs/数据集#L168)
- [四连肖，鼠猴猪蛇二十](/Users/wangci/my-electron-app/docs/数据集#L205)
- [五连肖复式，虎马猴鸡马猪各二十](/Users/wangci/my-electron-app/docs/数据集#L206)

当前结论：

- 这是组合命中玩法
- 不能展开成所涉生肖号码各一注

### B4. 连码/二中二类

样例：

- [新澳门：12-07，12-19，12-31，12-43，32-07，32-19，32-31，32-43，二中二每组5。](/Users/wangci/my-electron-app/docs/数据集#L263)

当前结论：

- 这是按“组”录入
- 不能拆回单号累计

## C 类：上下文行，不是录入条目

### C1. 地区切换行

样例：

- [老](/Users/wangci/my-electron-app/docs/数据集#L795)

样例：

- `[捂脸]`
- `@发财锐`

建议语义：

- 一律视为噪音
- 不应打断当前消息流

## E 类：歧义 shorthand，需要专门规则

### E1. 口语金额

样例：

- [一个一百二](/Users/wangci/my-electron-app/docs/数据集#L108)
- [一个三百六](/Users/wangci/my-electron-app/docs/数据集#L112)

建议语义：

- 民间口语通常表示 `120`、`360`
- 不能沿用普通中文数字规则直接算 `102`、`306`

### E2. 批量等号 shorthand

样例：

- [22=150, 27=150 31=100, 32=250...](/Users/wangci/my-electron-app/docs/数据集#L136)

建议语义：

- 这是“单号=金额”的批量写法
- 应逐项拆成多个单号普通单

### E3. 号码先发，下一行补金额

样例：

- [05-11-12-17-23-24](/Users/wangci/my-electron-app/docs/数据集#L769)
- [29-35-36-41-47-48各号10](/Users/wangci/my-electron-app/docs/数据集#L770)

建议语义：

- 第一行作为 `pending target`
- 第二行出现锚点金额后，与上一行绑定
- 长消息必须按整块处理，不能只按单行处理

### E4. 单号缺锚点

样例：

- [35.    号15块](/Users/wangci/my-electron-app/docs/数据集#L191)
- [44   100块](/Users/wangci/my-electron-app/docs/数据集#L193)
- [49号100#](/Users/wangci/my-electron-app/docs/数据集#L569)

建议语义：

- `号15`、`100块`、`100#` 都是金额表达
- 应优先尝试补成普通单，而不是直接报错

### E5. OCR 前缀污染

样例：

- [065＃01.13.37.49各10米，25号30米。](/Users/wangci/my-electron-app/docs/数据集#L213)

建议语义：

- 前缀 `065＃` 更像聊天编号/OCR 脏数据
- 不应把它当录入条目主体

### E6. 玩法词口语变形

样例：

- [猪的数各25](/Users/wangci/my-electron-app/docs/数据集#L813)
- [龙猪马猴蛇的数各三十](/Users/wangci/my-electron-app/docs/数据集#L832)
- [狗号各50](/Users/wangci/my-electron-app/docs/数据集#L534)

建议语义：

- `的数`、`号`、`各子十`、`个十` 都应视为普通单口语层
- 这类应归入普通单，而不是新玩法

## 最优解析策略

推荐解析顺序：

1. 先识别`上下文行`
   - 地区切换
   - 噪音标签
   - 摘要尾巴

2. 再识别`玩法单`
   - `平`
   - `特`
   - `连`
   - `二中二`
   - 其他不能安全展开的玩法

3. 最后才识别`普通单`
   - 显式号码
   - 生肖
   - 属性词
   - shorthand

4. 只有普通单进入`号码统计`

5. 玩法单单独记录到`玩法统计`
   - 如果当前不开放，则标记为`未开放玩法`
   - 但不要拖垮同一条长消息里的其他普通单

## 对当前项目的建议

建议先做三件事，不要继续堆“猜着展开”：

1. 增加`玩法拦截层`
   - 先把 `平/特/连/二中二/特码类` 拦出来

2. 增加`上下文继承层`
   - 支持 `老/新澳门/香港` 单独成行

3. 增加`普通单 shorthand 层`
   - 口语金额
   - 批量等号
   - 单号缺锚点
   - OCR 前缀清洗

## 当前阶段的开放边界

建议当前阶段：

- 开放：普通号码单、生肖单、属性单、上下文继承、噪音清洗
- 不开放：`平`、`特`、`连`、`二中二`

这样最稳，原因是：

- 不会把未开放玩法误统计进号码盘
- 不会因为长消息里混入一两行特殊玩法而整条失败
- 最接近数据集里的真实发单场景
