# A 模块测试用例

## 1. 文档范围

本测试文档基于当前实际代码整理，主要依据以下文件：

- `main.js`
- `public/auth.js`
- `public/index.html`
- `public/renderer-optimized.js`
- `public/messageProcessor.js`
- `public/userManager.js`
- `src/services/ModulePasswordRouter.js`
- `src/controllers/MainController.js`

本次测试范围包含：

- A 模块主流程
- A 模块设置、规则、统计、导出、数据上报
- 一条跨模块链路：`B -> 密码页 -> A`

本次测试范围不包含：

- B 业务本身
- OCR 图片识别
- 自动更新

说明：

- 本文档不把 `110` 进入 B 时触发的 A 数据清空维护动作当正式产品功能。

## 2. 优先级定义

- `P0`：主流程，必须优先通过
- `P1`：核心业务，影响日常使用
- `P2`：增强能力、规则配置、边界处理
- `P3`：低频功能、展示类、环境依赖能力

## 4. 执行建议

建议按以下顺序执行：

1. 先执行 `P0`
2. 再执行 `P1`
3. 然后执行 `P2`
4. 最后执行 `P3`

建议先准备一组覆盖以下场景的基础测试数据：

- 单客户数据
- 多客户数据
- 新奥、老奥、香港三类区域数据
- 含合法消息、ignored 行、blocking 行、未开放玩法、歧义消息的数据样本
